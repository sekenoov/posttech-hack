# Пробелы в базе знаний AI Jana

Журнал вопросов, на которые AI Jana не смогла ответить, и ответов, которые сотрудники отметили как бесполезные. HR разбирает журнал, выгружает его в Excel и превращает вопросы в новые разделы базы знаний.

## Что попадает в журнал

| Тип | Причина (`reason`) | Когда |
|---|---|---|
| `no_match` | `retrieval_below_threshold` | Ни один раздел базы не прошёл проверку релевантности |
| `no_match` | `llm_no_answer` | Разделы найдены, но LLM ответила `NO_ANSWER` |
| `negative_feedback` | `user_marked_unhelpful` | Сотрудник нажал «Не помогло» под ответом |

**Не попадает:** отказы по безопасности (чужие персональные данные, кадровые решения), личные ответы про остаток отпуска, ответы, где LLM была недоступна, но сотрудник получил цитату из базы.

Для `no_match` поиск по базе повторяется только на чтение, чтобы определить документ-кандидат (он становится категорией по умолчанию) и отличить отказ поиска от отказа LLM. Сам RAG, пороги и ответ сотруднику не меняются. Retrieval score в журнал не сохраняется.

## Приватность

- Кто задал вопрос, **не сохраняется**: в таблице нет поля пользователя.
- До записи маскируются email, телефоны, ИИН, номера карт и имена сотрудников из профилей (`[EMAIL]`, `[ТЕЛЕФОН]`, `[ИИН]`, `[НОМЕР]`, `[ИМЯ]`).
- Ключи, токены и промпты не записываются.
- Сбой записи не ломает чат: ошибка откатывается и пишется в лог одной строкой без данных.

## Для HR

Раздел **«Пробелы в базе знаний»** в меню «Управление» (только роль HR):

- поиск по вопросу, категории и комментарию; фильтры по статусу, типу и датам; пагинация;
- карточка записи: статус (`new` → `reviewing` → `resolved` / `ignored`), комментарий и **категория — выпадающий список документов базы знаний**, куда относится обращение (по умолчанию выбран документ-кандидат);
- **«Экспорт в Excel»** — выгрузка с текущими фильтрами;
- **«Создать статью»** — открывает «Редактор базы знаний» в выбранном в категории документе, с вопросом как заголовком нового раздела. Ничего не сохраняется и не публикуется, пока HR не напишет ответ и не нажмёт «Сохранить». После сохранения раздел сразу используется поиском — существующий механизм, индексация не менялась.

## API

| Метод | Путь | Доступ |
|---|---|---|
| POST | `/ai/feedback` `{question, answer_mode, source_ids[]}` | любой вошедший пользователь; событие анонимное |
| GET | `/admin/knowledge-gaps?q&status&event_type&date_from&date_to&page&page_size` | HR |

## Excel

Столбцы: Date, Question, Language, Feedback Type, Matched Document, Response Status, Review Status, Category (`ID: название документа`), HR Comment. Строка заголовков закреплена, включён автофильтр, ширина столбцов подобрана. Не более 10 000 строк.

**Защита от формул:** текст, начинающийся с `=`, `+`, `-`, `@`, табуляции или их полноширинных вариантов, записывается как строка с префиксом-кавычкой. В файле нет ни одной формулы, Excel ничего не выполнит при открытии. Это проверяется тестом по XML листа.

## Ограничения

- Язык определяется по символам (казахские буквы → `kk`, кириллица → `ru`, латиница → `en`) — это эвристика.
- Маскирование имён работает только для сотрудников из профилей; посторонние имена и опечатки в фамилиях не маскируются.
- Повторяющиеся вопросы не группируются: каждый вопрос — отдельная запись.
- Журнал не очищается автоматически; срок хранения — решение для production.
