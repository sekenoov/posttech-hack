# JanaМен — приёмочные тесты

Каждый сценарий проверяется дважды: вручную через UI (для демо) и автоматически на уровне API (`backend/tests/`). Сценарий считается пройденным, только если пройдены оба варианта.

Сопоставление с автотестами — в [COMPLIANCE.md](COMPLIANCE.md). Запуск: `docker compose exec backend python -m pytest` и `cd e2e && npx playwright test`.

Демо-аккаунты (пароль `JanaDemo2026!`): EMP — `employee@`, EMP2 — `erlan@`, MGR — `manager@`, MGR2 — `manager2@`, OUT — `timur@`, HR — `hr@janamen.example`. Условные обозначения:

- **EMP** — сотрудник Logistics Operations, руководитель MGR;
- **EMP2** — сотрудник того же отдела;
- **MGR** — руководитель Logistics Operations;
- **MGR2** — руководитель Customer Support;
- **OUT** — сотрудник Customer Support (подчинённый MGR2);
- **HR** — HR-администратор.

## S1 — Дашборд сотрудника

| # | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | EMP входит | Открывается дашборд JanaМен, sidebar с разделами сотрудника |
| 2 | Смотрит профиль | Ф.И.О., компания, должность, подразделение, руководитель, дата приёма, остаток отпуска — из backend |
| 3 | Пытается изменить должность | Поле недоступно; `PATCH /me` с `position` → 422 |
| 4 | Смотрит дашборд | Блоки: последние заявки, назначенное обучение, последние уведомления, быстрые действия |

API: `GET /me/dashboard` под EMP → 200 и все поля; без токена → 401.

## S2 — Согласование отпуска

| # | Шаг | Ожидаемый результат |
|---|---|---|
| 1 | EMP: «Мои заявки» → «Новая заявка» → даты, комментарий → «Отправить» | Заявка в списке со статусом «На рассмотрении»; в истории — запись «создана» |
| 2 | MGR: «Команда» | Видит заявку EMP |
| 3 | MGR открывает заявку → «Согласовать» | Статус «Согласовано», в истории — автор MGR и время |
| 4 | EMP | Уведомление «Заявка согласована», бейдж на колокольчике; клик ведёт в карточку заявки; остаток отпуска уменьшился |
| 5 | MGR повторно согласует / отклоняет ту же заявку | 409, статус не изменился |
| 6 | Отдельная заявка: MGR отклоняет с комментарием | EMP видит «Отклонено» и комментарий, получает уведомление |
| 7 | Подождать > 5 минут с новой pending-заявкой | Статус остаётся `pending` (автосогласования нет) |

API: `POST /requests` (EMP) → 201; `POST /team/requests/{id}/decision` (MGR) → 200; повтор → 409; история содержит 2 записи; у EMP появилось уведомление; дней больше остатка → 422.

| # | Шаг | Ожидаемый результат |

| 1 | HR: «Обучение» → назначить «Основы ИБ» сотруднику EMP со сроком | Назначение создано |

## S5 — AI Jana: ответ с источником

| # | Вопрос | Ожидаемый результат |
|---|---|---|
| 1 | «Сколько дней ежегодного отпуска положено?» | Ответ по документу политики отпуска + карточка источника `KB-LEAVE-001 · v1.0` |

API: `grounded=false`, `sources=[]`, `mode="refusal"`; «Обратиться в HR» → создаётся обращение и уведомление HR.
