# JanaМен — требования (Challenge 02 / DIGITAL HR)

Источник: `Jana_Post_Terricon_Hackathon_2026 1.pdf`, слайды 13–19. Ниже — требования организаторов, разбитые на проверяемые пункты. ID используются в IMPLEMENTATION_PLAN и ACCEPTANCE_TESTS.

## 1. Функциональные контуры (слайд «Что должна сделать команда»)

| ID | Контур | Минимальный результат по брифу |
|---|---|---|
| R1 | Единый вход и роли | Авторизация, минимум 3 роли: работник, руководитель, HR/администратор. Пользователь видит только разрешённые разделы и данные |
| R2 | Личный кабинет | Профиль: Ф.И.О., компания, должность, подразделение, руководитель, дата приёма, остаток отпуска, назначенное обучение, уведомления |
| R3 | HR-сервис | Минимум один рабочий сценарий заявки «Отпуск» или «Аванс»: создание, статус, история |
| R4 | Мои заявки | Единый список заявок: тип, дата, текущий статус, карточка заявки |
| R5 | Jana Academy | Каталог / назначенный курс, просмотр материала, фиксация прогресса и результата |
| R6 | AI Jana | Ответы на типовые вопросы только по базе знаний, показ источника, корректное «нет надёжного ответа» |
| R7 | Уведомления | Центр уведомлений: изменение статуса заявки, назначение / завершение обучения |

## 2. Границы MVP (слайд «Границы хакатонного MVP»)

| ID | Требование |
|---|---|
| B1 | Интеграции с 1С:ЗУП и Documentolog — mock API, но показать, где и как они подключаются |
| B2 | Официальные кадровые данные read-only: пользователь не меняет их напрямую |
| B3 | Достаточно адаптивной веб-версии |
| B4 | Не нужны: ЭЦП, хранение оригиналов документов, рекрутинг, Performance Management |
| B5 | AI не принимает кадровых решений |
| B6 | Персональные данные других работников недоступны без соответствующей роли |
| B7 | Тестовые данные: 3 роли, несколько заявок в разных статусах, 1–2 курса, небольшая база знаний; реальные ПДн не используются |

## 3. Ключевые сценарии демонстрации

| ID | Сценарий |
|---|---|
| S1 | Работник входит в JanaМен и видит профиль, быстрые сервисы, заявки, обучение, уведомления |
| S2 | Работник создаёт заявку на отпуск/аванс и видит изменение статуса |
| S3 | Руководитель видит разрешённую информацию по своей команде/заявке, но не чужие данные |
| S4 | Работник открывает назначенный курс, проходит материал/тест, видит прогресс |
| S5 | Работник задаёт AI Jana типовой вопрос и получает ответ со ссылкой на источник |
| S6 | На вопрос вне базы AI Jana не выдумывает, а сообщает об отсутствии информации / предлагает эскалацию в HR |

## 5. Нефункциональные требования («На что обратить внимание», «Правила»)

| ID | Требование |
|---|---|
| N1 | Простота: основные действия без инструкции, минимум шагов |
| N2 | Ролевая модель работает не только визуально — проверки на backend |
| N3 | Единый UX: профиль, заявки, обучение, уведомления и AI — одна платформа |
| N4 | AI-безопасность: не придумывать кадровые правила, не раскрывать чужие данные |
| N5 | Расширяемость: подключение 1С:ЗУП, Documentolog, новых HR-модулей |
| N6 | RU/KZ: переключение языка или архитектурная готовность к локализации |
| N7 | Запуск по понятной инструкции; Docker / docker compose приветствуется |
| N8 | В репозитории нет реальных ПДн, паролей, токенов, секретов |
| N9 | Явно указать: что реализовано полностью, что смоделировано, что оставлено на развитие |

## 6. Критерии оценки (слайд «Как оцениваем»)

| Критерий | Что оценивается | Вес |
|---|---|---|
| Сквозной сценарий | вход → профиль → заявка → статус/уведомление; обучение и AI встроены в общий опыт | 30% |
| Функциональность и UX | понятность, логика кабинета, минимум лишних действий, адаптивность | 20% |
| Архитектура и инженерия | роли и права, структура данных, API, качество кода, готовность к интеграциям | 20% |
| AI Jana | ответы по базе, источник, поведение без ответа, ролевой доступ | 15% |
| Jana Academy | курс, прохождение, прогресс/результат, связь с профилем | 10% |
| Презентация | ясность, ценность для работника и компании | 5% |

## 7. Дополнительные требования команды (внутреннее ТЗ)

- Workflow отпуска: статусы `pending / approved / rejected`, история изменений, автор и время решения, комментарий руководителя, уведомление сотруднику, запрет повторного решения и согласования чужих заявок.
- Jana Academy: 2 синтетических курса («Welcome to Jana Post», «Основы информационной безопасности»), quiz, прогресс переживает перезагрузку.
- AI Jana: Retrieval → Relevance check → LLM → Answer + Source; провайдер LLM настраивается через env; 5 синтетических документов с ID и версией; evaluation-тесты.
- UI-состояния: loading, empty, success, error, unauthorized, not found.
- Запуск: `docker compose up --build`, `.env.example`, seed, demo-аккаунты, инструкции по тестам.
