## 2. Найденные проблемы безопасности

| ID | Серьёзность | Проблема | Подтверждение |
|---|---|---|---|
| SEC-1 | Критично | `POST /auth/register` без авторизации принимает `role` — любой может стать HR | Проверено: создан пользователь `role=hr`, получен токен (тестовая запись удалена) |
| SEC-2 | Высокая | `PATCH /users/me` меняет `name` и `manager_id` — сотрудник может «назначить» себе другого руководителя | Проверено curl-запросом, значение возвращено обратно |
| SEC-3 | Высокая | `POST /leave/approve` проверяет только совпадение отдела: руководитель может согласовать свою заявку и заявки другого руководителя отдела | По коду `leave.py:approve_leave` |
| SEC-4 | Средняя | Автосогласование любых pending-заявок через 5 минут при любом GET | По коду `apply_auto_approvals` |
| SEC-5 | Средняя | Debug-логгер пишет email и префикс хеша пароля при каждом логине; лог закоммичен | `auth.py:_debug_log`, `backend/.cursor/debug.log` в git |
| SEC-6 | Средняя | Дефолтный JWT-секрет в коде, если env не задан | `config.py` |
| SEC-7 | Низкая | Загрузка документов без ограничения типа и размера | `users.py:upload_my_document` |
| SEC-8 | Низкая | Токен в `localStorage` — допустимо для MVP, фиксируем как известное ограничение | `AuthContext.jsx` |

## 3. Функции WorkHub вне scope кейса

Не требуются брифом, отвлекают на демо, а часть содержит выдуманные данные:

| Модуль | Состояние | Предложение |
|---|---|---|
| Payroll | Frontend-mock (`mockPayroll.js`), индийская модель CTC/HRA/PF/TDS + backend-таблица | Убрать из навигации и роутинга. «Аванс» как тип заявки — задел на потом |
| Attendance | Frontend-mock | Убрать |
| Wellness, Career, Complaints, Compliance | Рабочие, но вне кейса; Compliance частично пересекается с базой знаний | Убрать из навигации; Compliance-правила не переносим (знания AI Jana — только из `KnowledgeDocument`) |
| AI recommendations (OpenAI) | Работает только с ключом; генерирует «рекомендации» без источников | Убрать — противоречит требованию «без выдуманных AI-ответов» |
| Personalization panel, Landing page | Косметика WorkHub | Лендинг заменить на страницу входа JanaМен; персонализацию убрать |

Удаление делаем отдельным коммитом после согласования; код остаётся в истории git (тег `baseline-upstream`).

## 4. Что переиспользуем

- FastAPI-каркас, `database.py`, JWT/bcrypt (`auth.py`), `get_current_user`, `require_role`.
- Логику отпусков (подача, баланс, календарь) — расширяем, а не переписываем.
- TF-IDF retrieval из `chatbot.py` — ядро retrieval для AI Jana.
- MUI-тему (уже близка к бренду), `AuthContext`, axios-клиент, компоненты `LeaveApplication`, `LeaveList`, `LeaveCalendar`, `MyProfile` (переработка), `UserManagement`, `LearningManagement`.
- Docker-сборку frontend (multi-stage → nginx).

## 5. Вывод

Каркас пригоден, полный rewrite не нужен. Точечно заменяем три компонента, которые не доводятся до требований правками:

1. **Чат-бот** → новый модуль AI Jana (переиспользуем только retrieval).
2. **Learning** → модели курса, урока, quiz и назначения (текущая модель — только каталог ссылок).
3. **Навигация/layout** → единый `AppLayout` вместо двух navbar.

Остальное — расширение существующего кода.
